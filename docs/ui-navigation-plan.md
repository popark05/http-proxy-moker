# UI 내비게이션 개편 계획 (Bruno식 좌측 트리 + 탭)

작성: 2026-10-31. 아직 코드는 바꾸지 않았다.

## 1. 현재 구조의 문제

- `App.tsx`가 579줄이다. 상태 훅 조정, 핸들러, 모드별 레이아웃 두 벌(`mode === 'capture' | 'mock'`)이 한 파일에 있다.
- 화면은 TopBar → ProjectBar → SplitPane(좌: 프록시·기기·트래픽 / 우: 상세 또는 목+시나리오)로 쌓여 있다. 좌측 컬럼에 프록시 컨트롤, 기기 패널, 필터, 리스트가 모두 있어 낮은 창에서 답답하다.
- 시나리오 편집(`ScenarioEditor`), 케이스 라이브러리(`LibraryModal`), 계약(`ContractModal`, 364줄)이 모두 모달이다. 트래픽을 보면서 편집할 수 없고 한 번에 하나만 열 수 있다.
- 프로젝트 자산(캡처 세션, 시나리오, 라이브러리, 계약)을 한눈에 보는 목록이 없다.

## 2. 목표 레이아웃

```
┌─ TopBar: 로고 · [캡처|목킹] 모드 · 프로젝트명 ─────── CA ┐
│Rail│ Sidebar (트리)          │ 탭바: [GET /v1/user ×][시나리오 A ×]  │
│ 📡 │ ▾ 라이브 트래픽          │                                      │
│ 📱 │   ▾ api.example.com     │   워크스페이스 (선택한 탭의 내용)       │
│ 🧪 │ ▾ 캡처 세션 (3)          │   요청/응답 상세, 목 편집, 시나리오,    │
│ 📜 │ ▾ 목 (5)                │   계약 편집, 연결 마법사               │
│ ⚙ │ ▾ 시나리오 (2)           │                                      │
│    │ ▾ 케이스 라이브러리       │                                      │
│    │ ▾ 계약                   │                                      │
├────┴─────────────────────────┴──────────────────────────────────────┤
│ StatusBar: ● 프록시 :8080 · 기기 2 · 목 5개 활성 · 시나리오 A · 수정됨 │
└─────────────────────────────────────────────────────────────────────┘
```

## 3. 단계별 계획

각 단계는 독립적으로 머지할 수 있고, 단계마다 앱이 정상 동작해야 한다.

1. **App.tsx 분해 (UI 변화 없음)**: 핸들러를 `useProjectActions`, `useCloneActions`, `useScenarioActions` 등으로 분리하고 모드별 레이아웃 두 벌을 컴포넌트로 뺀다.
2. **셸 도입**: `AppShell`(Rail, Sidebar, Workspace, StatusBar). `ProxyControls`/`DevicePanel`은 Rail의 "연결" 섹션으로, 트래픽 리스트는 Sidebar로, 상세는 Workspace로 옮긴다. 겉모양만 바뀐다. 사이드바 폭/접힘은 `localStorage`에 저장하고 `SplitPane`을 재사용한다.
3. **탭 시스템**: `state/useWorkbench.ts`. 탭을 `{ kind: 'exchange' | 'mock' | 'scenario' | 'endpoint' | 'contract' | 'connect', id }` union으로 둔다. 열기/닫기/고정/순서 변경, `Cmd+W`, `Cmd+Shift+[` 단축키. `selectedId`를 탭으로 일원화한다.
4. **프로젝트 트리**: 목·시나리오·라이브러리·계약·캡처 세션을 트리 노드로 표시. 우클릭 메뉴, 활성 토글, mock-hit 배지, 시나리오 "수정됨" 배지.
5. **모달 → 탭 이전**: `ScenarioEditor`, `LibraryModal`, `ContractModal`/`ContractEditor`를 탭 콘텐츠로. 서버 설정과 CA 내보내기는 작아서 모달로 남긴다.
6. **모드 통합**: 캡처/목킹 레이아웃 분기를 없애고 모드는 상태바·TopBar의 전역 설정으로만 둔다. 프록시에 목을 다시 적용하는 effect는 유지한다.
7. **마감**: 커맨드 팔레트(`Cmd+K`), 사이드바 키보드 탐색, 빈 상태 안내, 접근성. 낮은 창과 Windows 타이틀바 확인.

1~3단계가 핵심 가치(레이아웃, 탭)이고 4~6단계는 점진 이전이다.

## 4. 리스크와 확인 사항

- **가상 스크롤**: 사이드바 폭 변경·탭 전환 시 `useVirtualBlankGuard`가 오동작할 수 있다. 리사이즈와 탭 전환에서 `TrafficList`를 검증한다.
- **Monaco**: 탭이 숨겨질 때 레이아웃이 깨질 수 있다. 탭은 언마운트하고 편집 상태는 훅에 두는 쪽을 권한다.
- **Windows 타이틀바**: TopBar의 `pr-[150px]`(win32)와 `pl-[84px]`(darwin) 처리를 유지한다.
- **설치본 검증**: 2단계와 5단계는 설치본에서 한 번씩 확인한다.
- **테스트**: 탭/트리 상태 로직은 훅 밖의 순수 함수로 빼서 `test/renderer`에서 단위 테스트한다.

## 5. 결정 (2026-10-31 확정)

- **Rail: 둔다.** 트리 섹션 전환과 연결 화면 접근을 Rail로 한다.
- **라이브 트래픽: 트리 노드로 시작.** 트래픽이 많아 불편하면 전용 탭을 나중에 추가한다.

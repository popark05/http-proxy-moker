# UX 구조 정리 계획 (엔티티 · 메뉴 · 용어)

작성: 2026-10-31 · 상태: 1단계 완료(2f3cbc7), 2단계 완료(9be5cbd), 3단계 완료(0984bc6), 4단계 구현됨(미커밋·앱 확인 전)

## 1. 배경과 목적

엔티티(트래픽, 목, 시나리오, 케이스 라이브러리, 컬렉션, 캡처 세션)의 목적은 분명하지만, **어디에 있고 언제 쓰는지**가 화면마다 달라서 어색하고 혼란스럽다. 각 엔티티가 "쓰는 기능" 안에 한 번만 나오도록 구조를 정리하고, 중복·잔재 개념은 줄이거나 삭제한다.

## 2. 진단

| # | 문제 | 근거 |
|---|---|---|
| 1 | 같은 자산이 여러 곳에 있다 | 목: 프로젝트 트리 + "목·시나리오" 탭 / 컬렉션: Rail + 트리 / 캡처 세션: 트리 + 트래픽 세션 메뉴 |
| 2 | 휘발과 저장이 섞여 있다 | 목(메모리 작업 공간)이 저장 자산과 같은 트리에 있다. 세션을 불러오면 실시간 목록을 대체하는데 표시가 없다 |
| 3 | 탭이 섹션과 무관하게 공유된다 | 트래픽 섹션에 목·시나리오 편집 탭이 따라와 보인다 |
| 4 | "모드"가 모호하다 | 캡처/목킹 토글은 실제로 "목 적용 여부"만 바꾼다. 목킹 모드에서도 캡처는 계속된다 |
| 5 | 개념의 층이 많다 | 목 · 케이스 · 케이스 라이브러리 · 시나리오 · 작업 공간. 저장 동작도 "케이스로 저장"과 "시나리오로 저장"으로 갈린다 |
| 6 | 프로젝트 필수/불필요 기능이 섞여 있다 | 목은 프로젝트 없이 되고 세션·컬렉션·시나리오는 필수. 안 열었을 때 안내가 약하다 |
| 7 | 경로가 둘인 동작 | 트래픽 → Bruno 직접 내보내기 vs 컬렉션에 추가 → Bruno 내보내기 |
| 8 | 화면 없는 잔재 코드 | 계약 시절의 배치 실행기(`contract:run`) 등 |
| 9 | 행 동작이 우클릭에만 있다 | 발견하기 어렵다 |

## 3. 원칙

1. **엔티티마다 집이 하나다.** 다른 곳에는 진입 링크나 동작만 둔다.
2. **휘발은 "지금", 저장은 파일.** 화면에서 한눈에 구분된다.
3. **섹션이 자기 탭을 소유한다.** 다른 섹션의 편집기가 따라다니지 않는다.
4. **사용자가 배워야 할 단어를 줄인다.** 코드 용어를 그대로 노출하지 않는다.

## 4. 목표 구조

### Rail (4개)

기기 연결 / 트래픽 / 목킹 / 컬렉션  (※ "프로젝트" Rail 메뉴는 폐지, 프로젝트는 상단 바의 이름 + 열기/새 프로젝트)

### 엔티티 지도

| 엔티티 | 성격 | 집 | 다른 곳에서의 진입 |
|---|---|---|---|
| 트래픽(실시간) | 휘발 | 트래픽 | 기기 연결의 접속 기기 → 필터 |
| 저장된 캡처 (구 "캡처 세션") | 저장 | 트래픽의 "보기 대상" | — |
| 현재 목 (구 "작업 공간") | 휘발 | 목킹 | 트래픽 행 우클릭 "목으로 복제", 상태바 배지 |
| 시나리오 | 저장 | 목킹 | — |
| 응답 케이스 (구 "케이스 라이브러리") | 저장 | 목킹 | 목 편집에서 자동 반영 |
| 컬렉션 요청 | 저장 | 컬렉션 | 트래픽 행 우클릭 "컬렉션에 추가" |

### 용어 변경

| 현재 | 변경 | 비고 |
|---|---|---|
| 작업 공간 | 현재 목 | 화면 문구만. 코드/CLAUDE.md의 "workspace"는 유지 |
| 케이스 라이브러리 | 응답 케이스 | |
| 캡처 세션 / 세션 | 저장된 캡처 | "세션"은 로그인 세션과 혼동 |
| 캡처/목킹 모드 | 목 적용 켜기/끄기 | 5단계 |
| 계약 | (컬렉션 요청) | 화면 용어는 이미 정리됨, 코드의 `Contract`는 유지 |

### 흐름

- 트래픽 → 저장된 캡처: "현재 목록 저장"
- 저장된 캡처 → 트래픽: 보기 대상을 바꿈(실시간은 뒤에서 계속 수집)
- 트래픽 → 현재 목: 우클릭 "목으로 복제"
- 현재 목 → 시나리오/응답 케이스: 목을 저장하면 응답 케이스로 자동 반영, "시나리오로 저장"
- 시나리오 → 현재 목: 활성화
- 트래픽 → 컬렉션: 우클릭 "컬렉션에 추가" (Bruno 내보내기는 컬렉션에서만)

## 6. 단계별 계획

각 단계는 타입체크·전체 테스트 통과 + 앱 확인 후 커밋한다.

### 0단계 — 기준 흐름 고정
이후 단계마다 앱에서 확인할 흐름을 정한다.
1. 기기 연결 → 캡처 → 목으로 복제 → 목킹으로 응답 확인
2. 시나리오 저장 → 활성화 → 수정됨 표시
3. 캡처 저장 → 저장된 캡처 보기 → 실시간으로 돌아오기
4. 컬렉션에 추가 → 편집 → 보내기 → Bruno 내보내기
5. 프로젝트 없이 시작 → 목 사용 → 저장 시도

### 1단계 — 삭제와 용어 정리 (위험 낮음)
- 삭제: `contract:run` IPC·preload·`ProxyService.runContracts`·워커 `runContracts`·`contract-runner`의 배치 실행·`ContractRunResult`·결과 스트림. 먼저 grep으로 사용처가 0인 것만 지운다(`bruno.ts`가 `validateShape`·`checkResponse` 계열을 쓰므로 그 부분은 남긴다).
- 삭제: 트래픽 행 우클릭 "Bruno로 내보내기"와 `useExchangeActions.exportBruno`.
- 프로젝트 트리의 "컬렉션" 그룹 제거.
- 화면 문구에 용어표 적용(현재 목, 응답 케이스, 저장된 캡처).
- 테스트: `contract-runner`·`contract`·`traffic-menu`·`project-tree` 관련 갱신.
- **완료 기준:** 같은 자산을 관리하는 화면이 하나뿐이고, 화면 없는 실행 경로가 없다.

### 2단계 — 목킹 Rail 화면과 탭 정리 (가장 큰 변경)
- Rail에 `mocking` 섹션 추가. 컬렉션처럼 전체 화면, 언마운트하지 않고 숨김(`AppShell`을 전체 화면 뷰 배열로 일반화).
- 화면 구성(안쪽 탭): **현재 목** (지금 `MockWorkspace`/`MockPanel` 내용 + 매칭 안 된 요청 차단) · **시나리오** (목록, 활성화, 저장, 편집, 상속은 "고급") · **응답 케이스** (지금 `LibraryModal` 내용).
- 시나리오 편집기·응답 케이스 편집은 전체 화면 안의 패널로 렌더(`variant="tab"` 재사용). 워크벤치 탭 모델에서 `mocks`·`scenario`·`library` 종류를 제거하고, 트래픽 섹션의 탭은 요청 상세만 남긴다.
- 목 저장 시 응답 케이스로 자동 반영(`upsertCase`), "케이스로 저장" 버튼 제거.
- 진입점 재배선: 복제 토스트의 "목킹 모드로", 상태바 활성 목 배지, 빈 화면의 "목 · 시나리오 열기", 커맨드 팔레트 → 목킹 섹션 열기.
- 프로젝트 트리의 "목" 그룹 제거.
- 테스트: `workbench`, `project-tree*`, `sidebar`(AppShell), `scenario-ui`, `commands`, `tab-bar`, `workspace` 갱신.
- **완료 기준:** 트래픽 섹션에는 요청 탭만 보이고, 목·시나리오·케이스 편집은 목킹 섹션에서만 한다.

### 3단계 — 트래픽의 "보기 대상" (실시간 / 저장된 캡처)
- `useCapture`: 실시간 목록(`live`)과 보는 대상(`view: live | saved(name)`)을 분리. 저장본을 보는 동안에도 실시간 이벤트는 계속 `live`에 쌓이고, 돌아오면 그대로 이어진다. 일시중지와 "지우기"는 실시간에만 적용.
- 트래픽 패널 상단의 "세션" 버튼을 **보기 대상 선택**(실시간 ▾ / 저장된 캡처들 / 현재 목록 저장…)으로 교체. 저장본을 볼 때는 "저장된 캡처 'x' 보는 중 · 실시간으로 돌아가기" 배너와 "실시간에 새 요청 N건"을 표시.
- 열린 요청 탭이 가리키는 id는 실시간·저장본 양쪽에서 찾고(`describeTab`), 없으면 "(지워진 요청)"으로 둔다.
- 프로젝트 트리의 "캡처 세션" 그룹 제거. 저장 위치는 그대로 `captures/`.
- 테스트: `useCapture`(보기 전환·실시간 누적), `traffic-menu`/패널, `commands`.
- **완료 기준:** 지금 보는 목록이 실시간인지 저장본인지 항상 보이고, 저장본을 봐도 실시간 수집이 끊기지 않는다.

### 4단계 — 프로젝트 Rail 폐지 (구현됨)
- Rail의 `project` 섹션, `ProjectTree`, `lib/project-tree`와 관련 테스트 제거. 저장된 `evermock.sidebar.section = project`는 `traffic`으로 대체.
- 상단 `ProjectBar`는 프로젝트 이름과 열기/새 프로젝트를 유지. 커맨드 팔레트는 목·시나리오·저장된 캡처·컬렉션 요청을 계속 검색.
- 대안(거부감이 있으면): 프로젝트 섹션을 읽기 전용 개요로 남긴다.
- **완료 기준:** Rail이 4개이고, 프로젝트 파일은 각 기능 안에서만 다룬다.

### 5단계 — 모드 재정의, 발견성, 프로젝트 없음
- 상단 캡처/목킹 토글 → **"목 적용" 스위치**(목킹 화면 상단과 상태바). 내부 값(`capture|mock`)은 유지하고 문구만 바꾼다. 켜면 프록시 자동 시작(이미 구현)과 연동.
- 행의 `⋯` 버튼: 트래픽, 컬렉션, 목 목록에서 우클릭 없이도 같은 메뉴를 연다.
- 프로젝트 없음: 저장 동작(시나리오·응답 케이스·저장된 캡처·컬렉션)이 막혔을 때 토스트에 "프로젝트 만들기 / 열기" 버튼을 둔다.
- 시나리오 상속 UI 접기(없으면 2단계에서 처리).
- **완료 기준:** 화면의 표현과 실제 동작이 일치하고, 막다른 길이 없다.

### 6단계 — 마감
- `CLAUDE.md`·`docs/` 갱신, 전체 흐름(0단계 5개)을 앱에서 확인, 설치본 확인(macOS 메뉴 단축키 포함, Windows 타이틀바).

## 7. 보류 · 범위 밖

- 작업 공간 = 시나리오 통합(수정됨/동기화 단순화): 2단계 이후 재평가
- 기본 프로젝트 자동 생성
- 코드의 `Contract` → 컬렉션 요청 이름 변경(변경 범위가 커서 별도)
- 라이브/저장 목록의 병렬 비교 보기

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 2단계가 탭·진입점·테스트를 많이 건드린다 | 단계를 둘로 나눠도 된다(2a 화면 신설, 2b 탭 제거). 진입점 목록을 먼저 만들고 하나씩 옮긴다 |
| 3단계에서 `useCapture` 상태 모델이 바뀐다 | 리듀서는 그대로 두고 "보는 대상"만 얹는다. 전환·누적 테스트를 먼저 쓴다 |
| 요청 탭이 저장본 id를 못 찾는다 | 실시간+저장본 양쪽 조회, 없으면 "(지워진 요청)" |
| 프로젝트 Rail 폐지에 거부감 | 4단계 대안(읽기 전용 개요)으로 전환 |
| 용어 변경이 문서·테스트 문구와 어긋난다 | 1단계에서 용어표를 한 번에 반영하고 이후 단계는 표를 따른다 |
| 메인/프리로드 변경은 앱 재시작이 필요하다 | 단계 확인 시 `npm run dev`를 완전히 재시작 |
